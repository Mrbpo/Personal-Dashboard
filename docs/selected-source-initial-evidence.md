# Explicit selected-source initial evidence

Related: #152, #68, #133. This is a development learning-answer input strategy; it changes no UI, storage schema, production setting, model, or public selection contract.

An existing `sourceHint.selectedDocumentTitle` must resolve uniquely to a current visible owner source, and its complete NFKC title must occur in the original question. With no hint, initial retrieval remains the existing whole-library ranked14 path. If the question exactly mentions another current visible source's full title, a small metadata query selects the whole-library path, including whole-library supplements. No aliases or comparison-word heuristics are used. Unnamed cross-source intent cannot be reliably inferred from a single title hint; that is an explicit limitation.

For an otherwise eligible selection, `readCompleteDocumentSource` performs its existing node/body/image metadata gates before loading original images. It must return every original node and required image, a complete current source/version/structure/image manifest, and verified original image bytes. The internal `selected-complete-initial-v1` proof binds these actual nodes, order, bodies, source identity, image identity/bytes and unchanged limits. It enters the planning fingerprint and generation receipt. This separate bounded path accepts complete initial evidence beyond14; ranked14/4 merge limits are unchanged. It executes no supplemental searches or extra model replan.

Existing limits remain512 nodes,131072 body codepoints,262144 body UTF8 bytes,64 images,32MiB image bytes,65536 image input token bound and300000 total request input bound, with the existing framing and schema enum/string limits. The actual contract-plan request must fit before choosing this path. Missing structure/images or size/request overflow journals an `initial-source-evidence` whole-library fallback with its reason and incomplete/unavailable manifest. Actual generation or later request capacity failures retain a `capacity-exceeded` receipt without another paid plan. Fallback caption/image capacity can still stop under its existing rules; no subset is relabeled complete.

Every planning/generation/audit re-read verifies the selected current source and complete manifest again; a changed selection, newly mentioned current source, unavailable reader or changed manifest stops. Original question-only contract requirements remain intact, including external comparisons not established by this source. The receipt's `selectedSourceInputCoverage: complete` concerns only the selected source's supplied input. Question coverage, whole-answer correctness and conflict exhaustiveness remain unassessed; missing requirements and insufficient answers remain possible. Parser warnings and unavailable parent receipts remain visible even when all original node bodies are present as anchors.

Verification uses mock-provider requests and focused PostgreSQL fixtures. It checks a paragraph outside ranked14 reaching the actual plan/generation input, original image binding, full-source proof tampering, unchanged no-hint behavior, unavailable/request-capacity/cross-title fallback, and current-version/manifest changes stopping the chain. These checks establish input coverage and guards, not semantic answer accuracy or three independent dataset acceptance. No paid calls, deployment or production switch are part of this change.
