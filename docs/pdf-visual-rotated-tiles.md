# 四 PNG 视觉视图的旋转页面支持（Issue 165）

范围为显式选页、图像输入且启用四图模式的既有转写入口。原页的 `/Rotate` 为 0、90、180、270 度（含等价的负角度及整周旋转）时，先把展示空间中的左上、右上、左下、右下区域反变换到原始 CropBox 用户坐标，再复制页面、设置派生视图边界。原旋转和内容流不改，不根据印刷页码猜方向。非直角旋转在所有选页开始处理前拒绝。

每个展示区域仍为页面宽高的 55%，相邻重叠 10%。四图的标签、提示词、schema、模型与 token 上限不改。仅四 PNG 模式的缓存身份更新为 `four-overlapping-png-v2` / `display-to-user-orthogonal-v1`，由原 PDF SHA 继续绑定实际旋转和 CropBox；旧缓存及已有结果保留。单图及四页 PDF 输入模式的行为和缓存 key 保持原样，本修复不扩展到这些模式。

验证仅使用合成资料：

- 两个聚焦检查通过，无失败或跳过：0/90/180/270、非零 CropBox 原点、非正方形区域、等价角度、拒绝未知角度；正式入口的四图顺序、原旋转/内容流保留、旧模式缓存兼容、渲染失败不请求。
- 一次 Poppler 批次渲染同一四色合成 fixture 的 16 个派生视图（四种旋转各四图），16 个中心像素均符合独立列出的展示方位；原 CropBox 原点为 `(10,20)`。实际 rotation 与内容流 SHA 逐视图核对一致。
- TypeScript 检查通过。没有真实课程页重跑、外部 AI 请求、PG 写入或生产变更。

本地原件及日志保存在 `data/issue165-validation/`（不纳入 Git），包括合成 PDF、16 张 PNG、渲染回执及聚焦检查日志。这个验证只证明裁剪方位和请求接线；不代表文字、公式或整页转写保真通过。
