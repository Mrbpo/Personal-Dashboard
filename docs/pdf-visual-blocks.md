# Selected-page visual blocks (Issue #183)

Explicit `pageNumbers` now uses `pdf-visual-selected-v4` and the same single visual request returns ordered `text` / `table` blocks. Prose, formulas, diagram descriptions, and captions stay in text blocks at their original reading positions. A table appears once as a grid; it is not duplicated as a LaTeX table or a second quote. The existing model, reasoning settings, 9000-output limit, request/day limits, and lack of automatic retries remain. Calls without a page selection retain their existing `visual_page_text` request and flat `pdf-visual-v1` cache.

## Table relations and searchable text

Cells retain zero-based origins, explicit row/column spans, original text, header role, and observed bold extent. `column` includes spanning parent column headers. `section` records a section label; it does not establish the end of a subsequent row group. The serializer preserves every header's role, coordinates, spans, and bold extent. Applicable section observations remain unresolved candidates and make that column path explicitly `complete=false`; they are never silently dropped or relabeled. Data between candidate column headers, or upper/lower spans that cannot form a containing chain, also makes the relationship unresolved. All observations remain present; the serializer neither picks the nearest header nor invents an old/new row-group scope. Declared column paths are derived only from supplied roles and spans, not visual or semantic inference.

For each ordinary cell, the search representation includes its row labels, ordered column headers, unresolved header candidates, and original value. String fields use a stated UTF-8 byte length followed by the original text, rather than JSON string quoting: inline math keeps its actual single backslashes and underscores in the query context. Those fields can be recovered by their byte length; the cached grid is the authoritative reconstruction artifact. The original cell/text fragments still pass the existing math-boundary and control-character checks. The serializer does not repair invalid math or a missing span.

The validator fails at the first invalid cell, overlap, out-of-bounds span, or uncovered grid slot. It does not fill gaps, merge cells, or accumulate an unbounded list of overlap messages. Bounds are 128 blocks, 8 tables, 100 rows, 64 columns, 2048 cells/table and 4096 cells/page. Original and derived search text each have a 100000-character capacity; exceeding it fails explicitly with the raw output retained on the error, without truncation or retry.

`visualTableHtml` escapes text and uses only declared spans. Both `th` and `td` explicitly use normal or bold weight; a header is not automatically bold. Mixed bold remains marked mixed, with no invented character positions. There is no claim to reproduce unexpressed character styling, caption styling, borders, pixel geometry, or complete page layout.

## Original observations and cache

When `LOCAL_OCR=true`, the existing local Tesseract binary can produce raw TSV from the already rendered full-page PNG. If only detail views or a derivative PDF are present, one full visible source page is rendered for this observation; no detail is mislabeled as the full page. The existing language setting is `eng+chi_sim`. The original TSV is not corrected, and its PNG identity, byte dimensions, raw SHA, and available/unavailable status are retained. Failure/oversize produces an explicit unavailable observation, not a claim that OCR succeeded. This adds no model phase or OCR component.

The cache key binds source PDF SHA, model/render/profile configuration, schema/protocol identity, and OCR policy. Its envelope retains physical-page/source binding, exact model-output JSON and SHA, actual request SHA, the unmodified OCR observation, and deterministic search text. Reading verifies identity and checksums, validates the original grid again, and regenerates exactly the stored search text. Old selected caches and raw results retain their old keys and bytes; they are never relabeled as v4 or used through an old-shape fallback. The existing source-observation profile retains its actual sidecar/request binding around this envelope. Page repair compares against the validated derived text, not the envelope JSON.

This is an integration into the existing selected-page repair/explicit visual branch. Ordinary unselected `visual_page_text` and the default Docling text projection have not thereby been upgraded. It does not mean that all website PDFs use typed blocks or that the final ingestion algorithm is complete. The next check is the existing failed PDF11; its actual result should inform later integration into the common ingestion path, rather than treating separate interfaces as the final architecture.

These are AI visual candidates and fallible OCR observations. They do not replace the original PDF/image, establish semantic truth, certify all characters, or become Docling native artifacts. Existing Docling raw/native artifact handling is unchanged. No UI, PostgreSQL schema, service, or production switch is added.
