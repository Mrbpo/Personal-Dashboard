# Selected-page visual blocks (Issue #183)

Explicit `pageNumbers` now uses `pdf-visual-selected-v4` and the same single visual request returns ordered `text` / `table` blocks. Prose, formulas, diagram descriptions, and captions stay in text blocks at their original reading positions. A table appears once as a grid; it is not duplicated as a LaTeX table or a second quote. The existing model, reasoning settings, 9000-output limit, request/day limits, and lack of automatic retries remain. Calls without a page selection retain their existing `visual_page_text` request and flat `pdf-visual-v1` cache.

## Table relations and searchable text

Cells retain zero-based origins, explicit row/column spans, original text, header role, and observed bold extent. `column` includes spanning parent column headers. `section` records a section label; it does not establish the end of a subsequent row group. The serializer preserves every header's role, coordinates, spans, and bold extent. Applicable section observations remain unresolved candidates and make that column path explicitly `complete=false`; they are never silently dropped or relabeled. Data between candidate column headers, or upper/lower spans that cannot form a containing chain, also makes the relationship unresolved. All observations remain present; the serializer neither picks the nearest header nor invents an old/new row-group scope. Declared column paths are derived only from supplied roles and spans, not visual or semantic inference.

For each ordinary cell, the search representation includes its row labels, ordered column headers, unresolved header candidates, and original value. String fields use a stated UTF-8 byte length followed by the original text, rather than JSON string quoting: inline math keeps its actual single backslashes and underscores in the query context. Those fields can be recovered by their byte length; the cached grid is the authoritative reconstruction artifact. The original cell/text fragments still pass the existing math-boundary and control-character checks. The serializer does not repair invalid math or a missing span.

The validator fails at the first invalid cell, overlap, out-of-bounds span, or uncovered grid slot. It does not fill gaps, merge cells, or accumulate an unbounded list of overlap messages. Bounds are 128 blocks, 8 tables, 100 rows, 64 columns, 2048 cells/table and 4096 cells/page. Original and derived search text each have a 100000-character capacity; exceeding it fails explicitly with the raw output retained on the error, without truncation or retry.

`visualTableHtml` escapes text and uses only declared spans. Both `th` and `td` explicitly use normal or bold weight; a header is not automatically bold. Mixed bold remains marked mixed, with no invented character positions. There is no claim to reproduce unexpressed character styling, caption styling, borders, pixel geometry, or complete page layout.

## Original observations and cache

When `LOCAL_OCR=true`, the existing local Tesseract binary can produce raw TSV from the already rendered full-page PNG. If only detail views or a derivative PDF are present, one full visible source page is rendered for this observation; no detail is mislabeled as the full page. The existing language setting is `eng+chi_sim`. The original TSV is not corrected, and its PNG identity, byte dimensions, raw SHA, and available/unavailable status are retained. Failure/oversize produces an explicit unavailable observation, not a claim that OCR succeeded. This adds no model phase or OCR component.

The cache key binds source PDF SHA, model/render/profile configuration, schema/protocol identity, and OCR policy. Its envelope retains physical-page/source binding, exact model-output JSON and SHA, actual request SHA, the unmodified OCR observation, and deterministic search text. Reading verifies identity and checksums, validates the original grid again, and regenerates exactly the stored search text. Old selected caches and raw results retain their old keys and bytes; they are never relabeled as v4 or used through an old-shape fallback. The existing source-observation profile retains its actual sidecar/request binding around this envelope. Page repair compares against the validated derived text, not the envelope JSON.

This is an integration into the existing selected-page repair/explicit visual branch. Ordinary unselected `visual_page_text` and the default Docling text projection have not thereby been upgraded. It does not mean that all website PDFs use typed blocks or that the final ingestion algorithm is complete. The next check is the existing failed PDF11; its actual result should inform later integration into the common ingestion path, rather than treating separate interfaces as the final architecture.

These are AI visual candidates and fallible OCR observations. They do not replace the original PDF/image, establish semantic truth, certify all characters, or become Docling native artifacts. Existing Docling raw/native artifact handling is unchanged. No UI, PostgreSQL schema, service, or production switch is added.

## Explicit source-bound native physical grids

`VisualPageOptions.nativeGridObservations?: PdfNativeGridObservation[]` is an explicit administrator-provided input, one sidecar for every selected physical page. There is no automatic native-grid producer, dependency installation, separate model stage or fallback. It requires explicit selection, original overview plus the four existing detail PNGs, and `gpt-5.4-mini`. It cannot be combined with `source-observation-v1`. Rotation must be zero, MediaBox/CropBox/rect must be identical and start at zero, and UserUnit must be absent or one. Missing/mismatched source, duplicate pages, unsupported geometry and schema capacity fail before the affected request; all selected sidecar/source/frame metadata is checked before the page loop. Each actual rendered overview must also match the supplied PNG SHA/dimensions before its request or cache read. The ordinary v4 request/schema/cache are unchanged when this option is absent.

The DTO is `version:'pdf-native-grid-v1', sourceHash, physicalPage, frame:{rect,mediaBox,cropBox,rotation}, image:{sha256,width,height}, producer:{name,version,policy}, nativeObservationSha256, grids:[{id,bbox,rowCount,columnCount,cells:[{id,row,column,rowSpan,columnSpan,bbox}]}], observations:{body,sha256}, sidecarSha256`. Boxes use the full original overview's top-left page coordinate frame, never detail-view pixels. The sidecar hash is SHA256 of `JSON.stringify` of that object excluding `sidecarSha256`; the observation hash covers its exact UTF-8 JSON body (at most 200000 bytes). Producer identity and hashes bind the supplied administrator observation; they do not authenticate arbitrary metadata or prove source visibility. Grid/cell IDs are page-unique bounded ASCII identifiers. Exact slot coverage, common physical boundaries, bounds and nonoverlap are required; unresolved boundaries are rejected without epsilon merging or invented geometry. The actual response schema is capacity-checked without truncating its source-ID list.

This route's `visual_native_grid_cells` response contains ordered `text` and `gridRef` blocks. A gridRef returns only its frozen grid ID/status and each frozen cell ID's text, content status and observed bold. The model cannot return row/column counts, indices, spans or boxes. Unknown/duplicate/missing IDs, `uncertain`/`not-table` grid status, uncertain cell content, incompatible blank/text or incomplete output preserve the original raw on the error and do not publish a cache. A model's `table` or `blank` declaration is still fallible; it cannot prove visibility, emptiness or semantics. Native text may have been covered, and raw OCR can invent letters in an empty bordered cell.

Assembly reuses the existing visual validator and HTML-compatible table representation with frozen geometry and every `headerRole:'none'`. All outside labels, captions, prose, math and diagram descriptions remain in their original text blocks. Each gridRef additionally returns `columnLabels:{status:'observed'|'none'|'uncertain',labels:[{fromColumnId,toColumnId,text}]}`. Column IDs are derived only from the frozen column count (`c0` onward); ranges must be legal and ordered. Labels are original-image visual candidates from the same request, never native text facts. `observed` needs a candidate; `none` must have an empty list and means **model-asserted-none, unverified**, not program-proven absence; `uncertain` stays explicitly uncertain. Text still passes the existing math/control gates. Cross-column label ranges do not imply a parent/child hierarchy, and no row-group relationship is invented.

The new search representation records each physical cell's ID/box, original length-framed value and applicable **AI-derived unverified** column-label candidates. It explicitly marks header/group associations **unassessed**, visibility unverified and semantic-table verification false. Column-label observations are a separate derivation field, not fake header rows or mutated source geometry. The serializer does not reuse the old empty-header-path `complete=true` wording. Text blocks still use the existing search validator/serializer. A geometry-valid page can therefore still fail actual header relations, transcription or whole-page fidelity; a later original-image review is necessary to establish whether those candidates are correct.

The separate `pdf-native-grid-cells-v1` cache identity binds the original selected configuration, actual sidecar, response schema and prompt. Its envelope stores actual source/page/model/parser binding, full sidecar, actual request SHA, unchanged OCR, **original gridRef provider raw**, raw SHA and a separately named deterministic derivation. Cache reads verify current sidecar/request/binding and recompute the derived content/search rather than trusting checksums alone. Original raw is never rewritten into assembled-table JSON. Old v4 or other policies cannot be relabeled as this route. No cache is published for unknown provider model, non-completed response or unresolved native-grid output. Original PDF/PNG/raw and previous scores remain authoritative evidence for later independent review; this feature establishes no overall fidelity or production acceptance.
