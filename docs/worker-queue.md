# Worker 长文档调度

关联 [Issue #64](https://github.com/Mrbpo/Personal-Dashboard/issues/64)。

## 行为

- 仍使用现有单个 worker。Docling 占一个被跟踪的异步槽；主循环继续处理来源同步、文档向量和旧后台队列。每轮优先处理最多一条 Outbox，再处理一条主队列任务，不无限排空 Outbox。
- Docling 槽忙时，领取任务排除 `docling_document`。新 primary 也会尊重 PostgreSQL 中另一个执行者尚有效的 Docling 租约；过期后才恢复。其他任务保持原有 `available_at,id` 顺序。
- 每个工作任务保持独立租约和续约。SIGTERM/SIGINT 停止领取新任务，最多等待 150 秒（现有容器停机宽限为 180 秒）；失去 primary 后不再续任务租约。不完成的任务保留远程任务 ID、已提交解析批次和向量游标，后继 worker 在租约过期后接管。请求已提交而远程 ID 尚未持久化的原有窗口仍存在，不能保证外部请求严格仅一次。
- `AiBudgetDeferredError` 表示请求尚未获预算批准。任务延期至实际重置时刻：日请求额度按 UTC 日，月预算按 America/Toronto 月；额度不足的领取不增加失败尝试次数，也不新增账本费用。完成过的批次与原费用保留。网络、HTTP、解析和凭据错误继续使用原失败规则。现有预算及请求上限没有提高。
- 自动文档向量补索引不复活 `failed`；启动及夜间自动索引不复活失败的 SQLite `index` 任务。已完成任务在确实缺索引时仍可排队。显式管理员/UI 重试入口保留；历史失败记录和 attempts 不被清空。本次不修复既有 Canvas/Piazza 授权或部分扫描错误。

## 证据与限制

2026-10-14 的只读生产检查发现 heartbeat 正常、Docling 在推进，而 103 条长解析与 5 条 Canvas 工作排在最早文档向量之前。旧实现逐份等待完整 Docling 转换，导致长解析阻塞向量；历史终态失败不会被 claim，不是由 22,000 条旧错误本身堵队列。

本补丁的三项针对性验证均已通过：单槽并行与停机边界、零 API 预算拒绝及 UTC/Toronto 重置、独立 PostgreSQL schema 中的任务排除/延期/过期恢复/失败向量保护。没有重复资料集检索、解析或付费调用。长时间来源同步仍占主执行槽，本补丁未增加通用并行执行器；正常同步准确性另行验收。

v1.1.0 已实际部署并切换，其 PDF/向量索引仍在处理中。本调度补丁的**代码完成、针对性测试通过**；**服务尚未部署、生产尚未应用本补丁**。须经过 PR、CI 和总调度审阅后按现有正式发布流程应用，不能把此文档或测试容器视为生产部署。
