# Native PDF region observations

In the existing select-then-answer visual-unit path, a registered native-region page is paired with its unique, already available full original PDF image only when document, current version, source version, source hash, evidence and physical page match. The literal page quotation members remain bound to that image through generation and the existing local citation check; text-only IDs for that paired page are not silently redirected. Crops, missing/ambiguous images, ordinary PDF pages without registered observations, and the legacy single-pass path retain their separate behavior. Pairing does not certify row/column meaning or guarantee that a model will preserve conditions. No additional image is fetched and no extra audit layer is added. The existing `author-image-caption-v1` wire identifier is retained for compatibility; native pairing is explicitly identified by its source-bound `nativeRegionObservation` metadata and literal members, not by that format name alone.

This is an administrator ingestion adapter, not a new truth source or an automatically enabled production parser. It supplements a complete native-text baseline through `KernelService.ingestNativeRegionText`, using the existing PostgreSQL source/version/evidence transaction and expected-current-version guard. Other enhanced/mixed baselines are rejected. Its own registered observations can be superseded after recovering the unchanged baseline and proving all previous region glyphs survive; identical observations are a guarded no-op.

`scripts/observe-pdf-native-regions.py` reads a pinned original PDF and an immutable Docling export. It uses declared table regions and their explicitly declared same-page captions only as untrusted bounding candidates. Caption glyph extents come from original characters whose centers are inside the declared caption box. The union must not cross another table. Literal ligatures and line-break hyphens are retained (`expand_ligatures=False`); a producer caption may disagree and remains preserved separately. Caption associations are not certified semantic relationships.

The producer records the full original page character inventory, character indices, bounding boxes, fonts, parser versions and options. A region that cuts a character, changes the non-whitespace character sequence or exceeds capacity is rejected. It does not repair cells, invent punctuation, infer row/column relationships, change Docling JSON or call a model. The companion Python environment needs the existing pdfplumber dependency; the application image gains no new dependency.

The adapter preserves each previous page body and appends eligible literal region text. A separate immutable manifest binds the additions and their offsets to the original source and current projected body. Unchanged pages and all previous versions remain preserved. Original page images must be available. The projection manifest and observation digests participate in version identity, including geometry-only changes.

Imports are trusted operator observations. A file hash proves identity, not that arbitrary caller-authored character JSON is authentic; there is no public upload endpoint for this adapter. Reading order, Unicode faithfulness and semantic relationships remain unverified, even after consistency checks pass. Uncertain cells are never promoted to canonical facts.

With the existing `producer-neighbors-v1` application option, the website's ordinary answer path can offer each whole region as a current-source quotation before selection. These windows do not replace other documents, silently expand selected citations or certify answer completeness. Prepared windows require a current source/body binding; caller JSON is insufficient.

The existing authenticated evidence GET accepts optional `nativeRegions=1` to return the registered observation for that physical page. The normal evidence/source/owner checks run first. Without that parameter the response is unchanged. No UI, page, database table or network service is added.

Verification must distinguish character consistency and citation transport from table fidelity, evidence recall and final answer correctness. A successful import, valid schema or HTTP 200 is not a content acceptance result.
